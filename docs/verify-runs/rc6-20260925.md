## What went wrong on the way, and why none of it is the product

1. **A first full run failed 40+ suites with one message** — `LEFT REAL ORG
   SETTINGS CHANGED: oe-group-foundation-poc.approval_tiers_enabled`. Staging's
   POC org had `approval_tiers_enabled = true` when the runner snapshotted it;
   `verify-approval-chain` restores it to `false` (the board's default, by
   design, see its header), so every later suite reported the same drift.
   Stopped, confirmed `false`, re-run. How it came to be `true` is unknown — an
   earlier killed run, or a person in the UI.
2. **Three suites "could not run"** — the dev server had been stopped by
   `taskkill //F //IM node.exe`, used to clear an `npm ci` file lock.
3. **`verify-finance-journey`: 1 check** — the payout fixture asserted an
   absolute payable total; staging's owned property already carried
   **₦7,560,000 of collected, unremitted rent**, so it read ₦8,010,000. The
   fixture had added exactly ₦450,000, the landlord's net — correct. Fixed in
   PR #61 to assert what each fixture ADDS against a baseline (and, newly, that
   an uncollected demand adds ₦0). ⚠️ **Open:** that ₦7.56M was not there at
   rc5's run. Unexplained until someone says whether staging UAT recorded rent.
4. **`verify-checkout-e2e` refused to start** — "the simulated gateway is
   disabled". Staging's local env file carried `VERCEL_ENV="production"` (the
   `vercel env pull` label for a project's Production environment, which makes
   localhost behave as production) and a **12-character `PAYSTACK_SECRET_KEY`**
   — not a key (a Paystack secret is 48), a placeholder. Both removed from
   `.env.staging.local`; the suite then passed with a plain `npm run dev`.
   `.env.prod.local` checked: no `PAYSTACK_SECRET_KEY` value (count 0), as 2.12
   requires.
5. **`Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`** — Node's own
   libuv assertion on Windows at process exit, printed AFTER a suite's verdict.
   Not a result; read the verdict line, not the last line.
