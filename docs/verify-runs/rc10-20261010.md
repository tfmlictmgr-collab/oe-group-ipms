## What the rc10 cut found before that run

The first full run failed **14 of 142** with one more unable to run. None of
them was a fault in the product shipped by #93. Two were faults in the
product or schema elsewhere, and both are fixed here:

1. **0315's index was missing on staging, and a suite was removing it
   (`0335`).** `sc_budgets_one_per_property_period_uidx` was still 0109's, with
   no `where status <> 'void'`, so voiding a budget did not free its
   property and period. The cause was `verify-sc-budget-uniqueness` §E, which
   rebuilt the index from a hard-coded copy of 0109's DDL after dropping it.
   Every full run on dev or staging stripped the clause again; it did so once
   more after 0335 was first applied. The suite now restores the definition it
   read. `0335` asks the catalogue, not the ledger, and does nothing where the
   index is right. **Production's index was already correct** (checked
   read-only), so 0335 is a no-op there. `verify-tenant-rent-payment`, which
   installs the vulnerable pre-0110 `create_rent_payment_intent` to reproduce
   its finding, now restores the fixed one in a `finally`.
2. **The triage prompt did not load from a CRLF checkout (`lib/triage.ts`).**
   On Windows the fence reads "```\r\n", nothing matched, and every inbound
   message was filed `classified_by = none` for human review. The repository
   copy is LF, so production (Linux) was not affected; one CRLF save would
   have done it there. Line endings are normalised before matching.
